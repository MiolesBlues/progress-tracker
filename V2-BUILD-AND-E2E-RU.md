## B01: причина и восстановление установки

В `44e3da3` были согласованы `package.json`, Bun 1.4.3, lockfile v3 и адресный override `@esbuild-kit/core-utils → esbuild 0.25.12`. Последующий коммит **`049ac70`** перевёл lockfile обратно в v1, убрал из него этот override и вернул вложенный `esbuild 0.18.20`, не меняя соответствующий `package.json`. Это подтверждено Git diff; версия инструмента, которым создан тот lockfile, неизвестна. Локальный `node_modules` отличался от lockfile и скрывал регрессию.

В пустой отдельной директории со старыми `package.json`, `bun.lock`, `bunfig.toml` воспроизведён отказ `bun install --frozen-lockfile --ignore-scripts`: **exit 1, overrides changed since bun.lock was saved**.

Lockfile перегенерирован поддерживаемым **Bun 1.4.3**, командой `install --lockfile-only --ignore-scripts`. Восстановлены формат v3 и уже существующий адресный override. `package.json` и `bunfig.toml` не менялись. Формат вложенных overrides и требование v3 описаны в [документации Bun](https://bun.com/docs/pm/overrides).

Сравнение всех разрешённых версий до/после:

- Все **83 прямые зависимости** сохранили прежние разрешённые версии.
- У всех оставшихся транзитивных узлов версии также сохранены.
- Удалены только отдельный `@esbuild-kit/core-utils/esbuild@0.18.20` и его платформенные узлы. Legacy loader теперь разрешает уже имевшийся `esbuild 0.25.12`; `tsx` сохранил собственный `0.28.2`.
- Новые overrides, массовый upgrade и `audit fix --force` не применялись. Имеющийся override `rolldown 1.2.1` не изменён.

Проверена новая установка **без прежнего node_modules и с изначально пустым отдельным кэшем**: frozen install установил 546 пакетов, exit 0. Повторный frozen install также прошёл, не изменив lockfile. Локальная установка приведена к тому же lockfile; прежние расхождения локальных React/Query и других пакетов не являются новыми изменениями lockfile этого этапа.

## Dependency security audit

В исходном lockfile V2 обнаружен один advisory: **GHSA-67mh-4wv8-2f99**, moderate, `esbuild 0.18.20` (исправление с 0.25.0).

Цепочка: dev dependency `drizzle-kit 0.31.11 → @esbuild-kit/esm-loader 2.6.5 → @esbuild-kit/core-utils 3.3.2 → esbuild ~0.18.20`. Уязвимость относится к development `serve` API; прикладной код его не вызывает, loader использует transform API. Доказанной эксплуатации через приложение нет. [Описание advisory](https://github.com/advisories/GHSA-67mh-4wv8-2f99).

Исправление — восстановленный адресный override **0.25.12**. Его совместимость проверена выполнением `transform`, `transformSync` и загрузкой TypeScript-конфига Drizzle без соединения с БД. Регрессионный toolchain-тест проверяет соответствие manifest/lockfile/версии Bun/CI и отсутствие старого вложенного узла.

Повторный **Bun audit: 0 уязвимостей, 596 проверенных пакетов, exit 0**. Остальные группы первоначального аудита остаются на исправленных версиях: shell-quote 1.12.0, brace-expansion 1.1.21/5.0.12, js-yaml 4.3.2, nanoid 3.3.20, source-map-js 1.2.2. Без необходимости не добавлялся глобальный override и не обновлялась вся цепочка сборки.

## B02: актуальные release E2E

Прежний locator «Пароль» стал неоднозначным после добавления подтверждения и кнопок глаза. Далее сценарии искали старую кнопку «Создать аккаунт», удалённый inline input нового упражнения и отдельное состояние «Сохранено». Поэтому успешный build не означал работающую сквозную проверку нового UI.

Устаревшие локаторы заменены доступными `getByRole` / `getByLabel` с точным именем, где нужно. Сценарии выполняют текущие действия пользователя, не подменяя их существованием кнопок:

1. Вход/регистрация, несовпадение и подтверждение пароля, показать/скрыть, Enter, правильный autocomplete; подтверждение отсутствует в signup payload.
2. Onboarding с 1, 2, 4 и 7 днями; touch-сценарии дополнительно создают 3 дня. Произвольные длинные названия и отсутствие интерактивных пресетов.
3. Выбор дня, длинные названия, добавление/переименование дня, порядок клавиатурой, мышью и сенсорными событиями; сохранение порядка после reload и откат при отказе RPC.
4. Диалог добавления упражнения с тремя полями и правильным UUID выбранного дня; редактирование целей без веса с сохранённым выбором дня.
5. Полное автозаполнение `50 кг, 8/8/7/6, RIR 2`, изменение одного подхода, десятичная запятая, черновик после reload.
6. Потеря ответа после INSERT, retry с тем же UUID и ровно одной строкой; автоматический переход с собственными весом/повторениями следующего упражнения и сохранением даты.
7. Обновление last-entry после сохранения, устаревший cache/refetch, поздний ответ при ручном вводе, старый pristine черновик следующего упражнения.
8. Toast без блокировки формы, одно уведомление при следующем сохранении, исчезновение примерно через 3 секунды; его полный bounding box выше dock.
9. Отдельные «Записи», фильтры сегодня/7/30/всё время, несколько сессий одного дня, вес по возрастанию/убыванию и стабильный порядок одинакового веса.
10. Пагинация HTTP при искусственном серверном maxRows=2, будущие записи исключены; три метрики графика; архив упражнения/дня сохраняет историю в дневнике и прогрессе.
11. A→B→A: программа, история и черновики изолированы, возвращается только свой черновик; ошибка сети отличима от пустого состояния, Retry восстанавливает экран.

Все внешние запросы перехватываются: разрешён только фиктивный `workout-e2e.invalid`, остальные внешние адреса блокируются. **Это E2E реального UI с мокированным backend**, не проверка настоящих Supabase Auth/JWT/RLS, SMTP, OAuth или транзакций production.

### Мобильные проверки

Оба движка Chromium и Playwright WebKit: **320, 375, 390, 430 px**. Проверяются overflow, реальные date/weight inputs и их bounding boxes относительно друг друга/колонок, production CSS fixture, onboarding, модальные окна, Select и его keyboard focus, dock/toast, длинные названия и Drag & Drop.

TouchSensor проверяется синтетическими `TouchEvent` через Playwright dispatchEvent, с удержанием и движением по кадрам; проверены первый→последний день, reload и ошибка сети. Это проверка обработчиков приложения. Нативный доверенный жест ОС, физический iPhone, системная клавиатура, VoiceOver и фактическая safe-area устройства **не проверены**. Ограничения Playwright: [Touchscreen](https://playwright.dev/docs/api/class-touchscreen), [эмуляция touch-событий](https://playwright.dev/docs/touch-events).

Перед измерениями тесты ждут окончания анимаций и активации sensor; перед новым reorder — подтверждения предыдущего RPC. Известная ошибка приложения **B13** при drag во время другого сохранения остаётся вне этого этапа. UI ради тестов не менялся.

Итоговый полный прогон E2E: **28/28 PASS**, Chromium 14/14 и WebKit 14/14, 0 failed, 0 skipped, 0 flaky, retries=0. Продолжительность 5,2 минуты. Все четыре ширины проверены в обоих движках.

## Остаточные проблемы и релиз

1. **B09 остаётся production-риском:** отзыв TRUNCATE подготовлен и локально проверен в первом этапе, но здесь не применялся. Избыточные остальные/default privileges требуют отдельного анализа и согласования.
2. **B05–B08, B10–B13** не входят в этот этап и не объявляются исправленными: выбор дня программы, ошибка за диалогом, NULL day_id в дневнике, длинный DOM истории, Auth spacing, тема toast, TOCTOU создания упражнения и drag во время busy.
3. Настоящий Supabase с двумя JWT, реальные redirects/email, конкуренция транзакций, backup/restore и физический iPhone требуют отдельной staging-приёмки по [E2E-RELEASE-RU.md](docs/E2E-RELEASE-RU.md).
4. Удалённая Ubuntu CI ещё не подтверждена; локальный проход Windows не выдаётся за её запуск. Есть прежнее optional-peer ограничение Vite/esbuild.
5. Версия Bun внешнего редактора, создавшего `049ac70`, неизвестна. Будущая перегенерация lockfile другим инструментом может вернуть расхождение; frozen install и новый toolchain-тест должны оставаться обязательными gates.

Исправление B01/B02 и успешная сборка сами по себе не означают готовность к публичному запуску. Общий вердикт остаётся **NO-GO** до отдельного разрешения production grants и критической staging-приёмки. Дальнейшие исправления в этом этапе не выполняются.
